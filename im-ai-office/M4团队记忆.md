## 2. 数据模型（增量，SQLite）

```sql
-- 术语表（团队记忆核心增量）
CREATE TABLE IF NOT EXISTS term (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  term        TEXT NOT NULL,
  meaning     TEXT NOT NULL,
  source      TEXT DEFAULT 'manual',  -- manual | corrected
  created_at  TEXT DEFAULT (datetime('now')),
  UNIQUE(term)
);

-- 群简介：给 grp 补 intro 字段（有则用，无则空）
-- ALTER TABLE 由 init_db 判断：若 grp 表无 intro 列则只读方案，先存内存/扩展表
-- 最小实现：新增 grp_meta(oim_group_id, intro, ai_enabled)
CREATE TABLE IF NOT EXISTS grp_meta (
  oim_group_id TEXT PRIMARY KEY,
  intro        TEXT DEFAULT '',
  ai_enabled   INTEGER DEFAULT 1,   -- 1=旁听 0=关闭
  updated_at   TEXT DEFAULT (datetime('now'))
);
```

## 3. 记忆来源双通道

### 3.1 主动录入（低成本）
- 建群/进群时填「群简介」→ 写 `grp_meta.intro`
- 管理员可手动加术语：`POST /api/term/add {term, meaning}`
- 人/称谓：注册时填（已有 person/alias）

### 3.2 被动沉淀（核心，自动）
用户**驳回/修改/纠正** AI 产出时，提取修正信号 → 沉淀为记忆：

| 触发 | 提取 | 落库 |
|---|---|---|
| 驳回时选「负责人错了」→ 给出正确人 | 更新 alias 指向 | `alias` 增行（source=corrected） |
| 驳回时选「时间错了」→ 给出正确时间 | （任务修正） | task 更新 + audit |
| 纠正术语/称呼 | term 增/改 | `term` 增行（source=corrected） |
| 手动加术语 | —— | `term`（manual） |

> 复用现有 `reject_task(con, task_id, reason)` 的回传：reason 里带「负责人/时间/术语」类别，触发对应沉淀。见 §5。

## 4. 注入与溯源

### 4.1 注入上下文（intent_detect 增强）
`process_message` 处理群消息时，自动把「群简介 + 术语表 + 人/别名」拼进 `sys_ctx`：

```python
def build_sys_ctx(con, group_id):
    ctx = []
    gm = get_grp_meta(con, group_id)
    if gm and gm.get('intro'):
        ctx.append(f"【群简介】{gm['intro']}")
    terms = list_terms(con)
    if terms:
        ctx.append("【术语】" + "；".join(f"{t['term']}={t['meaning']}" for t in terms))
    aliases = list_aliases(con)
    if aliases:
        ctx.append("【人称】" + "；".join(a for a in aliases))
    return "\n".join(ctx)
```

`intent_detect(msg, sys_ctx)` 已有 sys_ctx 注入位，直接拼入。

### 4.2 消歧用
- 术语/称谓命中 → 用「自己的定义」，而非模型通用理解
- 人名歧义：`alias` 命中多个 → 触发确认（已有 `resolve` 逻辑）

### 4.3 引用溯源
AI 产出标注「依据：术语 X（Y 于 Z 定义）」。MVP 简化为：确认卡/任务卡片带「依据」小字，指向 `term.meaning` 或 `alias` 命中结果。

## 5. 修正信号 → 沉淀闭环（核心）

新增函数：

```python
def memorize_corrective(con, sender, correction_type, payload):
    """correction_type: person/term/deadline
    - person: 更新 alias（把某称呼绑定到正确 person）
    - term: 新增/覆盖 term
    - deadline: 只更新 task，不沉淀为长期记忆
    """
    audit(con, f"user:{sender}", "memorize", {"type": correction_type, "payload": payload})

def resolve_assignee_reply_reject(con, sender, reply, task_id):
    """被 @ 者回复'不是我/换人' → 提取正确人 → alias 修正 + task 重指 + audit"""
```

**触发点**：
- `reject_task` 带 `reason` 含类别 → 调 `memorize_corrective`
- `resolve_assignee_reply` 用户纠正 → 调 `memorize_corrective`
- 私聊消歧中用户选了候选 → 更新 alias 权重/指向

## 8. 范围裁剪（MVP）

- ✅ 做：术语表 + 群简介注入 + 人称别名 + 修正信号沉淀 + 溯源标注
- ❌ 不做：历史消息自动挖掘、向量检索、决策日志、跨群共享记忆
- ⏳ 接受：术语表用手动 + 纠正两通道（暂不做自动挖掘）；仅注入当前群、小团队 token 可控
