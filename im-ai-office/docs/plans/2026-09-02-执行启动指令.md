## 执行范围与方式

1. 全量执行 P0（monorepo + Electron）→ P1（Drizzle）→ P2（Hono RPC）→ P3（自建聊天层 + OpenIM 停用），按顺序推进。
2. 用户已授权连续执行：**计划中「阶段间 ≥3 天观察窗口」经用户豁免，压缩为阶段间汇报点**。每 3 个 Task 一批，完成后汇报本轮验证输出，然后继续下一批（不要停下来等反馈）；阶段边界（各验收清单全绿）同样汇报后继续。
3. **停下等用户的三类情况**：① 验收不达标且无法自修；② Spec 之外需要产品决策；③ **到达 P3 切流日前——需用户确认切流日期，并完成 app_user 密码分发**（Spec §4.3，切流日全员要能用新密码登录）。另：Task 0.5 的 Electron 打包安装与中文实测需要用户在真机配合，届时明确请求用户在场。
4. 分支策略：用户已同意直接在 main 上逐 Task 提交（单人内部仓库，不做 worktree）；每阶段完成打 tag 并**推送远端含 tags**（`git push origin main --tags`）——push 失败（VPN/代理未通）视为阶段未完成，汇报后重试，不许静默跳过。

## 环境自查（每个阶段开工前重跑）

- **所有命令先 `cd` 到仓库根 im-ai-office/，以下相对路径均以此为基准。**
- 原生 PG：`C:\imai\pgsql\bin\pg_isready.exe -h 127.0.0.1 -p 5432`，未运行则 `C:\imai\pgsql\bin\pg_ctl.exe -D C:\imai\pgdata -l C:\imai\pglog.txt start`
- 后端：8000 未响应则 `cd backend-ts && npx tsx src/index.ts`（DATABASE_URL=postgresql://imai:imai_secret@127.0.0.1:5432/imai）
- P3 开工前：启动 Docker Desktop（OpenIM 的 Mongo 导入需要）；Mongo dump 用 `docker exec mongo mongodump --archive=C:\imai\backups\openim-final.archive`（主机无 mongodump）
- E2E 失败重跑：先清 event_dedup（`DELETE FROM event_dedup`）或更换唯一文本尾缀，再重试

## 安全护栏（多天自主执行期间）

- `.env`、`deploy/openim.env` **永不提交**（已移出跟踪）；不提交任何含密钥/密码文件
- 每阶段 tag 后必须 push（含 --tags），远端备份才算完成；LLM_API_KEY 余额不足时停下汇报
- P3 切流前：检查 C 盘剩余空间 ≥10GB，校验两份 dump 文件非空，落盘 C:\imai\backups
- 识别质量观察：跑完 P3 后向用户建议重启质量主线（质量报告 + D3 难例）
- 收尾环节以「全量验收清单」替代 finishing-a-development-branch（用户已授权 main 直执行）

## P3 特别约束（Spec §4.2 修订版 + §8 评审修订）

切流前 pg_dump + Mongo dump 双快照同一时点、打 tag openim-era-final；AI 入口内联进发送端点（processMessage + clientMsgID 闸门平移，确认/提醒链路不断）；message 表加 UNIQUE(conv_id, client_msg_id)；**OpenIM 6 容器只 stop 不删除**（保留 2-4 周观察期）；切流窗口消息丢失声明写入交接文档。
