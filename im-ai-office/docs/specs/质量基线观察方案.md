# 识别质量基线观察方案

> 日期：2026-08-31 ｜ 前置：识别质量统计已上线（commit 4ea050a，真机验收 12/12）
> 目标：用真实使用数据建立质量基线，达到阈值时触发 prompt/阈值调优提案。数据积累期不写代码、不改 prompt。

## 1. 观察节奏

- **每周一 10:00** 自动跑一次 `python scripts/quality_report.py --days 7`（Proma 定时任务「IMAI 识别质量周报」），同时跑 `--days 30` 看月度趋势。
- 结果摘要回复到会话；明细滚动记录在项目级 Context：`.context/automation/imai-quality-baseline/notes.md`。
- 数据为空（本周无 AI 触达）→ 只回一行说明，不告警。

## 2. 基线指标与分级（来源：内部产品规划-一页纸 验收标准 + 识别质量统计Spec）

| 指标 | 绿 | 黄 | 红 | 依据 |
|---|---|---|---|---|
| 一次确认通过率 one_pass_rate | ≥80% | 70–80% | <70% | 产品验收标准「80% 以上任务一次确认通过」 |
| 高置信误判（conf≥0.8 仍被驳回占比） | <5% | 5–15% | >15% | 高置信才弹卡的产品约束 |
| 挂起任务（未定归属）最老 age | ≤2 天 | 2–5 天 | >5 天 | 每日汇总兜底应在下班前消化 |
| 处理延迟 P95 | ≤10s | 10–30s | >30s | 确认卡要跟得上对话节奏 |

## 3. 触发调优的规则

- **连续 2 周同一指标落在黄区**，或**任意一周落红区** → 当次周报里输出调优提案（改 prompt 措辞 / 置信度阈值 / 归属分流规则），写入 notes.md 的「待办调优」区，并提示用户开新会话执行（提案不自动改代码）。
- 驳回原因 Top1 连续两周占比 >40% → 单独给出针对该原因的 prompt 修改建议。
- 指标全绿连续 4 周 → 基线即告稳定，建议把该周数据写回交接文档作为正式基线，任务可降频为每月一次。

## 4. 边界（不做）

- 不自动修改 prompt / 阈值 / 代码；调优一律以提案形式供人决策。
- 不做自动告警、标注队列、前端质量面板（识别质量统计Spec §5 明确不做）。
- 周报只读，不写任何数据（脚本特性保证）。
