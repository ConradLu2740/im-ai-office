# IMAI · 时刻点 Deadline 解析 Spec（D3-② 收口）

> 时间：2026-09-02 ｜ 背景：交接文档已知问题 #1-②——"12点56分"等**时刻点**表达解析缺失，`deadline` 文本留在库里但 `deadline_at` 为空 → 提醒调度失效（产品验收线"有截止、到期有人被提醒"的直接缺口）｜ 关联：《提醒调度与缺陷修复Spec.md》§1.2（原解析器 Spec）、2026-09-02 质量基线首宣判
> 目标：`imai/services/deadline_parser.py` 补时刻点解析，零 LLM、确定性原则不变；回填机制（scheduler 每轮 `backfill_pending`）不改，新规则自动生效。

---

## 1. 需求

| 输入模式 | 示例 | 语义 |
|---|---|---|
| 纯时刻点 | 12点56分 / 12点半 / 9点 / 14:30 / 12时30分 | 今天该时刻；**已过则明天**（时刻点语义=未来的那个时点） |
| 时段+时刻 | 下午3点 / 晚上8点半 / 上午10点 / 中午12点 | 时段折算后同上 |
| 日期+时刻 | 明天下午3点 / 周五下午2点前 / 25号上午10点 / 今晚8点 | 日期 + 具体时刻（不再是 23:59） |
| 仅日期 | 明天 / 周五 / 3天后 / 月底 | **现状不变**：当天 23:59（回归保障） |

## 2. 设计

- `parse()` 重构为两段：先 `_extract_time`（正则抠出 时刻+时段前缀，返回 (hour, minute) 与剩余文本），再走**原有日期分支**（作用于剩余文本，逻辑不动）。
- 时段折算：`下午/晚上/傍晚/夜里/晚` 且 h<12 → +12；`中午` 且 h<12 → +12；`上午/早上` 不变。
- 归一化：`今晚→今天晚上`、`明晚→明天晚上`、`明早→明天早上`（使剩余文本仍命中原日期分支）。
- 组装规则：
  - 日期命中 + 时刻 → 日期当天的该时刻
  - 仅时刻 → 今天该时刻（`<= now` 则 +1 天）
  - 仅日期 → 23:59（现状）
  - 都没有 → None（现状）
- 非法时刻（h>23、m>59，如"25点"）→ 时刻整体忽略，退回纯日期路径（不引入错误 deadline）。

## 3. 测试（guard_remind/test_parser.py 增补，固定 now=2026-08-28 10:00）

- 纯时刻点未来/已过两个方向（"12点56分"→当天 12:56；now=13:00 时 → 次日 12:56）
- "12点半"→12:30、"14:30"→14:30、"下午3点"→15:00、"晚上8点半"→20:30
- "明天下午3点"→8-29 15:00、"周五下午2点前"→8-28 14:00、"25号上午10点"→8-25 10:00、"今晚8点"→当天 20:00
- 回归：原 13 个用例全部不动且继续通过；"25点"→None；"尽快"→None

## 4. 边界与明确不做

- "晚上12点"歧义（口语指午夜）按 12:00 处理，观察期再调
- "三点一刻"中文数字、"X刻"不支持
- 跨月相对表达（"下下周五"）沿用原边界不支持
- LLM 的 deadline_hint 输出格式不改（自由文本 → 解析器兜住）
