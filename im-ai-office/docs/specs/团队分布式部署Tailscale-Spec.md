# 团队分布式部署 Spec（Tailscale 虚拟局域网）

> 2026-09-03 · v1 · 待用户批准后实施
> 背景：IMAI 团队成员分布不同区域/网络，需要都能访问部署于主机（10.159.200.253）的 IMAI 服务。用户明确：团队愿意以本软件作为群聊工具（内部闭环），手中无云服务器，偏好数据不出域。

## 1. 目标

- 分布式团队成员（预估 5-10 人）在不同网络下均可通过浏览器访问 IMAI（登录/聊天/看板全功能）
- 数据不出域：消息与业务数据始终只存在于用户主机 PostgreSQL
- 零公网暴露：不在路由器开端口、不租云服务器
- 成本：¥0

## 2. 方案选型

| 方案 | 数据出域 | 公网暴露 | 成本 | 结论 |
|---|---|---|---|---|
| **Tailscale 虚拟局域网** | 否（端到端 WireGuard 加密直连） | 无（不开任何端口） | 免费（100 设备内） | ✅ 采用 |
| 路由器端口映射 + DDNS | 否 | 是（密码明文过公网，无 HTTPS） | 免费 | ❌ 安全不达标 |
| frp 内网穿透 + VPS | 元数据过 VPS | 是 | ¥50+/月 | ❌ 多花钱多风险 |
| 云服务器部署 | 是（整个库在云上） | 是 | ¥50-100/月 | ❌ 与偏好相悖 |

## 3. 架构

```
[成员A 家里]   Tailscale 客户端 → 100.x.x.x ─┐
[成员B 公司]   Tailscale 客户端 → 100.x.x.x ─┼─ WireGuard 加密直连（P2P，打洞失败时经
[成员C 差旅]   手机 Tailscale  → 100.x.x.x ─┘   中继加密转发，第三方无法解密）
                                                    │
                              [主机 10.159.200.253 + Tailscale 100.x.x.x]
                              IMAI 后端 :8000 + PostgreSQL（数据唯一所在地）
```

- 每台设备一个**固定虚拟 IP**（100.x.x.x），换网络/换地方不变
- 成员浏览器访问 `http://<主机虚拟IP>:8000`，体验与局域网完全一致

## 4. 账号与安全设计

1. **Tailscale 账号**：采用单账号共享模式（用户的 Google/GitHub/微软账号登录，所有成员设备登同一账号）——10 人内最简；副作用是成员设备可管理该虚拟网（内网工具可接受）。后续可升级为 Tailscale 组织邀请制
2. **IMAI 账号**：沿用已开通的成员账号（zhangwei/zhangmin/lina/xiaozhangwei）
3. **加固项（实施时一并做）**：admin 初始密码 123456 → 更换为强密码（远程可达后不应保留弱口令）
4. **现状声明**：IMAI 部分管理端点无鉴权（既有内网姿态）；Tailscale 网内成员即"半个内网"，风险可接受，不再额外加签
5. 传输安全：WireGuard 加密（应用层 HTTPS 可选二期，用 Tailscale 证书能力）

## 5. 实施步骤

### 5.1 主机（我做，需用户配合一次登录）

1. `winget install tailscale` 安装
2. 启动后弹出浏览器 → 用户登录身份账号（Google/GitHub/微软任选）
3. `tailscale ip -4` 取主机虚拟 IP，**此 IP 长期固定，即团队的新访问地址**
4. 验证 Tailscale 开机自启（默认随系统服务，无需配置）
5. 复核 IM 仍正常（8000 监听、SSE hello）

### 5.2 成员（发给同事的三步说明书，我做文档）

1. 下载安装 Tailscale（Windows/macOS/手机均有官方包，地址写入说明书）
2. 登录与主机相同的身份账号
3. 浏览器打开 `http://<主机虚拟IP>:8000` → IMAI 账号登录

### 5.3 加固（我做）

- admin 密码更换（新密码用户提供，或生成随机密码交付）
- 交接文档更新：部署章节改为"分布式模式"，记录虚拟 IP 与成员清单

## 6. 验收清单

- [ ] 主机 `tailscale status` 在网
- [ ] 任一成员设备（非主机网络）打开虚拟 IP 地址 → IMAI 登录页可达
- [ ] 成员登录 → 进群 → 发消息 → 主机与成员实时互见（SSE 生效）
- [ ] 主机断网/关机时成员端明确表现为"无法访问"（预期行为，非故障）
- [ ] admin 强密码生效

## 7. 风险与边界

| 风险 | 评估 |
|---|---|
| Tailscale 协调服务器（控制面）不可用 | 已建立的设备连接不受影响；仅新设备首次加入需要协调面在线。概率低；极端情况可自建 Headscale（二期） |
| 主机依赖 | 主机常开是硬前提（与局域网方案相同，非新增风险）；长期建议专用小主机 |
| 成员设备丢失 | 设备上仅 Tailscale 客户端 + 浏览器缓存的登录态；IMAI 会话 30 天过期，可在主机侧换密码踢下线。可在 Tailscale 后台移除该设备 |
| 免费版限额 | 100 设备 / 3 用户（个人版按登录账号计 1 用户）——共享单账号模式下仅计 1，远够 |

## 8. 回退

任一成员卸载 Tailscale 即退出虚拟网；主机卸载后回到纯局域网模式。IMAI 本身零改动。

## 9. 明确不做（二期以后）
